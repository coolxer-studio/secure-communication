# Secure Communication protocol v1 接入与调试指南

本文面向需要在现有 HTTP 业务链路中接入 Secure Communication SDK 的服务端、
Web、Host、Java、Android 和 iOS 开发人员。示例基于协议 v1 和国际算法套件：

```text
P-256 + HKDF-SHA256 + AES-256-GCM
```

SDK 在 HTTP 或 HTTPS 之上保护业务 method、逻辑 path、受保护 header、请求 body 和
响应 body，并提供服务端身份固定、安装身份确认、完整性校验与重放防护。生产建议
HTTPS；SDK 不隐藏目标地址、流量大小和时序，也不会自动重试业务请求。

## 1. 先理解接入后的请求链路

```text
业务调用方
  └─ SecureClient.request(业务 method、逻辑 path、header、body)
       ├─ 首次或会话过期：POST /sc/v1/handshake
       ├─ 完成双向证明：POST /sc/v1/handshake/finish
       └─ 加密业务请求：POST /sc/v1/message
            └─ 服务端解密并包装为原始业务请求
                 └─ 原 Controller / Service
                      └─ 响应加密后返回客户端
```

外层网络请求始终是 `POST /sc/v1/message`。原始 method、逻辑 path、受保护
header 和 body 都在密文内，现有 Controller 的参数模型通常无需改变。服务端必须
用 `LogicalRouteAuthorizer` 明确允许可被安全隧道访问的逻辑路由。

仓库当前没有 Git tag。表中版本来自 manifest 或 module path，只表示源码状态；不能据此
断言 npm、Maven、PyPI 或远端 Go/Swift 制品已经发布。下文优先给出本地源码接入方式。

所有客户端都需要以下配置：

- `baseUrl`：使用 HTTP 或 HTTPS 的服务端根地址，生产环境建议 HTTPS；
- `appId`：由服务端分配并加入握手白名单的应用标识；
- `serverTrustAnchors`：`serverKeyId -> P-256 SPKI Base64URL` 映射；
- `deviceType`：`H5`、`HOST`、`SERVER`、`EMULATOR`、`ANDROID` 或 `IOS`；
- 安装身份存储和超时配置。

`serverTrustAnchors` 是公开信任锚，不是秘密，但必须通过可信构建流程分发。服务端
私钥、会话记录保护密钥和一次性注册令牌不得进入客户端产物或源码仓库。

## 3. 推荐接入顺序

1. 生成服务端身份密钥和会话记录保护密钥。
2. 选择 Spring、Go 或 Python 服务端实现，配置 Redis、握手授权、路由白名单和 CORS。
3. 用服务端公钥生成客户端 `serverTrustAnchors`。
4. 先接通一个客户端，确认握手、finish、message 三段链路。
5. 接入其余客户端并运行同一套协议测试向量和业务回归用例。
6. 上线前确认企业传输策略和服务端 TLS 强制配置，切换 KMS/密钥文件和生产 Redis。

服务端身份密钥或 `keyId` 未确定前不要构建正式客户端，否则客户端固定的公钥与
服务端返回身份不一致，握手会失败。

## 4. 生成开发环境密钥

以下命令仅用于本地或集成测试。不要为用户提供固定的默认私钥。

```bash
mkdir -p .local/sc-dev
chmod 700 .local/sc-dev

openssl genpkey -algorithm EC \
  -pkeyopt ec_paramgen_curve:P-256 \
  -out .local/sc-dev/server-private.pem

openssl pkey \
  -in .local/sc-dev/server-private.pem \
  -pubout \
  -out .local/sc-dev/server-public.pem

openssl pkcs8 \
  -topk8 -nocrypt \
  -in .local/sc-dev/server-private.pem \
  -outform DER \
  | openssl base64 -A | tr '+/' '-_' | tr -d '='

openssl pkey \
  -pubin -in .local/sc-dev/server-public.pem \
  -outform DER \
  | openssl base64 -A | tr '+/' '-_' | tr -d '='

openssl rand 32 | openssl base64 -A | tr '+/' '-_' | tr -d '='
openssl rand -hex 32

chmod 600 .local/sc-dev/server-private.pem .local/sc-dev/server-public.pem
```

四段输出依次用于：

1. 服务端 P-256 PKCS#8 私钥；
2. 服务端 P-256 SPKI 公钥，也是客户端信任锚的 value；
3. 32 字节 Redis 会话记录保护密钥；
4. 管理端注册接口鉴权令牌（如果宿主实现该接口）。

建议记录公钥指纹并通过独立渠道核对：

```bash
openssl pkey -pubin -in .local/sc-dev/server-public.pem -outform DER \
  | openssl dgst -sha256
```


### 5.2 基础属性

生产建议：

```yaml
spring:
  sc:
    enabled: true
    v1:
      enabled: true
      prefix: /sc/v1/message
      require-tls: true
      allowed-suites:
        - P256_HKDF_SHA256_AES256_GCM
      clock-skew: 2m
      replay-ttl: 10m
      session-ttl: 10m
      max-envelope-bytes: 600000
      max-plaintext-bytes: 400000
      max-body-bytes: 262144
```

SDK 通用业务 body 默认上限是 1 MiB。业务系统应根据实际需要主动收紧；例如业务
body 最大为 256 KiB 时，`max-body-bytes` 才是解码后的业务 body 上限；`max-plaintext-bytes`
包含保护对象 JSON 和 body 的 Base64URL 表示，`max-envelope-bytes` 又包含密文的
Base64URL 表示。后两者必须预留 JSON、两层 Base64URL 和 AEAD 标签的膨胀空间。
上面的 400000/600000 能覆盖 256 KiB body 及常规 header，修改 header 上限或
payload 格式后应重新执行边界测试，而不是直接照搬。

Starter 的默认值如下：

| 属性 | 默认值 |
| --- | --- |
| `spring.sc.enabled` | `false` |
| `spring.sc.v1.enabled` | `true` |
| `spring.sc.v1.prefix` | `/sc/v1/message` |
| `spring.sc.v1.require-tls` | `false` |
| `spring.sc.v1.clock-skew` | `5m` |
| `spring.sc.v1.replay-ttl` | `10m` |
| `spring.sc.v1.session-ttl` | `10m` |
| `spring.sc.v1.max-envelope-bytes` | `1400000` |
| `spring.sc.v1.max-plaintext-bytes` | `1048576` |
| `spring.sc.v1.max-body-bytes` | `1048576` |

官方客户端始终请求 `/sc/v1/message`，信封 AAD 中的 path 也固定为该值。除非网关继续
对外暴露固定入口并映射到内部路径，否则不要修改 `spring.sc.v1.prefix`；Go 和 Python
服务端的同名配置遵循相同约束。

`allowed-suites` 当前应只保留 `P256_HKDF_SHA256_AES256_GCM`。服务端消息层的 Provider
扩展点不能单独形成新套件；现有握手、密钥派生和全部客户端都固定为国际套件。

### 5.3 必须提供的宿主能力

Starter 默认失败关闭。仅设置 `spring.sc.enabled=true` 并不能形成可用的生产服务。
宿主至少需要提供：

| Bean/SPI | 责任 |
| --- | --- |
| `ServerIdentityProvider` | 返回 `keyId`、公开身份公钥并对握手 transcript 签名 |
| `SessionRepository` | 保存 pending/active 会话；集群使用 Redis |
| `ReplayProtector` | 原子认领 `session + direction + seq` |
| `InstallationRegistry` | 保存已注册安装身份公钥 |
| `EnrollmentTokenService` | 签发并单次消费原生端注册令牌 |
| `HandshakeAuthorizer` | 校验 appId、deviceType、H5 Origin 等准入条件 |
| `LogicalRouteAuthorizer` | 只允许必要的 method + 逻辑 path |

Starter 自带以下可组合实现：

```java
new P256ServerIdentityProvider(keyId, privateKey, publicKey);
new AesGcmSessionRecordProtector(sessionRecordKeyBytes);
new RedisSessionRepository(redis, "sc:v1:session", recordProtector);
new RedisReplayProtector(redis, "sc:v1:replay");
new RedisInstallationRegistry(redis, "sc:v1:installation");
new RedisEnrollmentTokenService(redis, "sc:v1:enrollment");
```

不同用途必须使用独立 Redis 前缀，不得与业务幂等 key 混用。会话记录中包含会话
密钥材料，必须再用 `SessionRecordProtector` 加密后写入 Redis。

一个最小授权与路由白名单示例：

```java
@Bean
HandshakeAuthorizer handshakeAuthorizer() {
    Set<String> appIds = Set.of("example-web", "example-agent");
    Set<String> h5Origins = Set.of("http://localhost:8888");
    return context -> {
        boolean appAllowed = appIds.contains(context.appId());
        boolean originAllowed = !"H5".equals(context.deviceType())
                || h5Origins.contains(context.origin());
        if (!appAllowed || !originAllowed) {
            throw new SecureProtocolException(SecureErrorCode.HANDSHAKE_FAILED);
        }
    };
}

@Bean
LogicalRouteAuthorizer logicalRouteAuthorizer() {
    return (method, path) ->
            ("POST".equals(method) && "/attach/start".equals(path))
            || ("POST".equals(method) && "/attach/upload".equals(path))
            || ("POST".equals(method) && path.matches("/cross/[^/?]+"));
}
```

路由授权接收规范化后的逻辑 path 部分，不包含 query。业务需要约束 query 参数时，
还应在 Controller/业务校验层继续校验。生产代码不要使用“允许所有 path”或简单的
`startsWith("/")`。

### 5.4 加载服务端身份密钥

开发环境可从环境变量读取 Base64URL 编码的 PKCS#8/SPKI。核心转换方式如下：

```java
byte[] privateDer = Base64.getUrlDecoder().decode(privateKeyBase64Url);
byte[] publicDer = Base64.getUrlDecoder().decode(publicKeyBase64Url);
KeyFactory factory = KeyFactory.getInstance("EC");
PrivateKey privateKey = factory.generatePrivate(new PKCS8EncodedKeySpec(privateDer));
PublicKey publicKey = factory.generatePublic(new X509EncodedKeySpec(publicDer));

return new P256ServerIdentityProvider(keyId, privateKey, publicKey);
```

生产环境优先由 KMS/HSM provider 完成签名。无论使用哪种方式，都不得把私钥写入
`application.yml`、镜像层、构建产物或日志。

### 5.5 H5 CORS 配置与过滤器顺序

浏览器会对三个 `/sc/v1/**` POST 发起预检。CORS 必须在安全消息过滤器之前处理。
Starter 的安全过滤器顺序是 `-200`，建议注册顺序更小的 `CorsFilter`：

```java
@Bean
FilterRegistrationBean<CorsFilter> secureCommunicationCorsFilter() {
    CorsConfiguration cors = new CorsConfiguration();
    cors.setAllowedOrigins(List.of("http://localhost:8888"));
    cors.setAllowedMethods(List.of("POST", "OPTIONS"));
    cors.setAllowedHeaders(List.of("Content-Type"));
    cors.setAllowCredentials(false);
    cors.setMaxAge(3600L);

    UrlBasedCorsConfigurationSource source = new UrlBasedCorsConfigurationSource();
    source.registerCorsConfiguration("/sc/v1/**", cors);
    FilterRegistrationBean<CorsFilter> registration =
            new FilterRegistrationBean<>(new CorsFilter(source));
    registration.setOrder(-300);
    return registration;
}
```

不要把业务 `code` 暴露为外层 CORS header。它应通过 `protectedHeaders` 放进密文。
`Origin`、`Referer` 和 `Sec-Fetch-*` 受浏览器约束，保留在外层，只用于 H5 握手
准入，不能单独作为密码学身份凭据。

如果启用了 Spring Security，还需要允许 `OPTIONS /sc/v1/**` 通过预检，并保证
CORS Filter 位于 Security 和安全消息 Filter 之前。

### 5.6 现有 Controller 如何复用

安全过滤器解密成功后会把请求包装成原始业务 method、path、header 和 body，再
交给 Servlet 链。现有 Controller 可以继续使用：

```java
@PostMapping("/attach/upload")
public UploadResponse upload(
        @RequestHeader("code") String code,
        @RequestBody RequestVO request) {
    return uploadService.handle(code, request);
}
```

需要删除或拒绝原明文入口，避免调用方绕过 `/sc/v1/message` 直接访问 Controller。
可通过网关路由、网络分区或独立内部 Dispatcher 限制明文路径；仅配置逻辑路由白
名单并不自动阻止外部网络直接请求原 Controller。

### 5.7 服务端 SDK 选择

| SDK | 适用宿主 | 接入对象 | 并发/状态模型 |
| --- | --- | --- | --- |
| Spring Boot | Servlet、Spring MVC | Starter、Filter、Bean/SPI | Spring 生命周期；内存或 Redis |
| Go Server | 标准库或兼容 `net/http` 路由器 | `http.Handler` 包装器、Go interface | goroutine 安全；内存或 `go-redis/v9` |
| Python Server | FastAPI 或其他 ASGI 应用 | FastAPI 握手路由、ASGI Middleware、Protocol | async/await；内存或 `redis.asyncio` |

三种实现使用同一入口、错误码、Redis key 语义和测试向量，默认均关闭且失败关闭。
宿主必须提供 P-256 身份、握手授权、注册令牌、逻辑路由白名单和生产状态实现。

### 5.8 Go 服务端接入

源码内使用：

```bash
cd server/go
go test ./...
```

从消费项目引用当前本地源码：

```bash
go mod edit -require=github.com/coolxer/secure-communication-server-go@v0.0.0
go mod edit -replace=github.com/coolxer/secure-communication-server-go=/absolute/path/to/secure-communication/server/go
```

只有确认远端存在实际发布 tag 后，才改用 `go get module@tag`。

Go 根包提供协议核心与 SPI，`httpadapter` 包装业务 Handler，`redisstore` 提供生产
状态。最小装配如下：

```go
config := securecommunication.DefaultConfig()
config.Enabled = true
config.MaxEnvelopeBytes = 600000
config.MaxPlaintextBytes = 400000
config.MaxBodyBytes = 262144

messages, err := securecommunication.NewMessageService(
    sessions, replay, config, securecommunication.AESGCMAlgorithm{},
)
if err != nil {
    return err
}

handshakes := &securecommunication.HandshakeService{
    Identity: identity, Sessions: sessions, Installations: installations,
    Tokens: enrollmentTokens, Authorizer: handshakeAuthorizer, Config: config,
}

secured := httpadapter.New(
    config, handshakes, messages, logicalRouteAuthorizer, businessHandler,
)
```

生产状态使用 `redisstore.SessionRepository`、`ReplayProtector`、
`InstallationRegistry` 和 `EnrollmentTokens`，会话仓库使用
`NewAESGCMRecordProtector(recordKey)`。`Memory*` 实现仅用于测试和单节点开发。

`httpadapter` 解密后克隆 `http.Request`，重写 method、URL、query、header 与 body，
并将传输信任信息放入 context。业务代码可以通过
`httpadapter.TransportTrustFrom(request.Context())` 读取认证状态。

启用 `RequireTLS` 后，Go SDK 只依据 `request.TLS` 判断安全连接，不自动信任
`X-Forwarded-Proto`。在反向代理后部署时，由受信代理或宿主中间件正确建立 TLS 状态。

完整接口与 Demo 说明见 [Go Server SDK](../server/go/README.md)。

### 5.9 Python 服务端接入

源码安装和验证：

```bash
cd server/python
python -m pip install '.[test]'
python -m pytest
python -m build
```

消费项目也可以直接安装当前源码目录：

```bash
python -m pip install /absolute/path/to/secure-communication/server/python
```

`pyproject.toml` 的 `1.0.0` 是源码声明，不能据此断言 PyPI 已存在该版本。

FastAPI 应用需要同时注册握手路由和 ASGI 消息中间件：

```python
config = Config(
    enabled=True,
    max_envelope_bytes=600000,
    max_plaintext_bytes=400000,
    max_body_bytes=262144,
)
messages = MessageService(sessions, replay, config)
handshakes = HandshakeService(
    identity, sessions, installations, enrollment_tokens,
    handshake_authorizer, config,
)

app = FastAPI()
install_fastapi_routes(app, handshakes, config)
app.add_middleware(
    SecureCommunicationMiddleware,
    config=config,
    messages=messages,
    routes=logical_route_authorizer,
)
```

生产状态位于 `secure_communication_server.redis_store`，使用异步 Redis 客户端和
`AESGCMRecordProtector`。核心 SPI 使用 Python `Protocol` 和异步方法，宿主可以
替换为自己的 KMS、数据库或策略实现。

中间件解密后重写 ASGI `scope` 和 `receive`，捕获下游 `send` 事件并加密完整响应。
业务应用可从 `scope["sc.transportTrust"]` 与 `scope["sc.sessionId"]` 读取认证上下文。
中间件只信任 `scope["scheme"] == "https"`，代理头解析必须放在受信代理边界。

完整接口与 Demo 说明见 [Python Server SDK](../server/python/README.md)。

## 6. Web/H5 接入

### 6.1 安装与配置

从源码打包并在消费项目安装：

```bash
cd client/javascript
npm ci
npm pack --pack-destination /tmp/sc-pack
# 切换到消费项目后：
npm install --save-exact /tmp/sc-pack/coolxer-secure-communication-js-2.0.0.tgz
```

只有确认组织 npm 仓库已经发布 `2.0.0` 后，才直接按包名安装。

```js
import { SecureRequest, createSecureClient } from '@coolxer/secure-communication-js';

const client = createSecureClient({
  baseUrl: 'https://api.example.com',
  appId: 'example-web',
  deviceType: 'H5',
  serverTrustAnchors: {
    'server-key-2026': '<P-256 SPKI Base64URL>'
  },
  credentials: 'omit'
});

await client.initialize();

const response = await client.request(new SecureRequest({
  method: 'POST',
  logicalPath: '/attach/start',
  contentType: 'application/json',
  protectedHeaders: { code: 'installation-h5-app-version' },
  body: JSON.stringify({ common: [] })
}));

if (!response.ok) {
  throw new Error(`business request failed: ${response.status}`);
}
const result = response.json();
```

默认身份存储是 IndexedDB。安装私钥由 WebCrypto 生成且不可导出；清除站点数据、
隐私模式退出或浏览器策略禁用 IndexedDB 后会生成新的安装身份。

H5 不调用 `enroll(token)`。它的首次准入依赖服务端公钥固定、Origin 白名单和安装
密钥持有证明。WebCrypto 通常只在 HTTPS 或浏览器认可的安全上下文中可用；不要把写在
JavaScript 中的 `appKey` 当成秘密。

### 6.2 HTTP 与 HTTPS 配置

客户端直接接受 HTTP 和 HTTPS，传输协议由企业运行时配置决定；生产环境建议使用
HTTPS。例如测试环境可直接配置 HTTP：

```js
const client = createSecureClient({
  baseUrl: 'http://127.0.0.1:11099',
  appId: 'example-web-dev',
  deviceType: 'H5',
  serverTrustAnchors: {
    'server-key-dev': '<与服务端一致的 P-256 SPKI Base64URL>'
  }
});
```

服务端默认不强制 TLS。企业需要只允许 HTTPS 时，Spring 设置
`spring.sc.v1.require-tls=true`，Go 设置 `Config.RequireTLS=true`，Python 设置
`Config(require_tls=True)`。使用 HTTP 时仍会执行应用层服务端信任锚校验、加密和重放
保护，但不会隐藏目标地址、流量大小、时序和外层传输元数据。

不要直接双击 HTML 以 `file://` 打开。使用本地 HTTP 服务器，让浏览器携带稳定的
Origin，例如：

```bash
npx http-server ./demo -p 8888
```

H5 在非安全上下文中可能无法取得 WebCrypto，并返回 `SC_CRYPTO_UNAVAILABLE`；普通
非浏览器客户端不受此限制。服务端 CORS 和握手白名单必须使用精确 Origin
`http://localhost:8888`。`localhost` 与 `127.0.0.1` 是两个不同 Origin。

### 6.3 通用 H5 页面集成

页面应在创建客户端前准备运行时配置，不要把服务端公钥、appId 或 URL 硬编码到
SDK 源码。下面示例假设消费项目已把 ESM 产物部署到 `vendor/`：

```html
<script type="module">
import { createSecureClient } from './vendor/secure-communication/index.esm.js';

const runtimeConfig = {
  appId: 'example-web-dev',
  baseUrl: 'http://127.0.0.1:11099',
  serverTrustAnchors: {
    'server-key-dev': '<与服务端公钥一致的 P-256 SPKI Base64URL>'
  }
};

const client = createSecureClient({
  ...runtimeConfig,
  deviceType: 'H5'
});
await client.initialize();
</script>
```

缺少 `appId`、`baseUrl` 或信任锚时，应用应在初始化阶段直接失败，不应发起网络请求。
配置补齐后重新加载页面，在 Network 面板中应依次看到：

1. `/sc/v1/handshake` 返回 2xx；
2. `/sc/v1/handshake/finish` 返回 2xx；
3. `/sc/v1/message` 返回加密响应。

会话有效期内后续上报通常只出现 `/sc/v1/message`。

当前仓库没有 `v2.0.0` tag。从消费项目引用本地 module：

```bash
go mod edit -replace=github.com/coolxer/secure-communication-go/v2=/absolute/path/to/secure-communication/client/go
```

```go
package main

import (
    "context"
    "os"
    "path/filepath"
    "time"

    sc "github.com/coolxer/secure-communication-go/v2"
)

func newClient() (*sc.Client, error) {
    configDir, err := os.UserConfigDir()
    if err != nil {
        return nil, err
    }
    return sc.New(sc.Config{
        BaseURL:    "https://api.example.com",
        AppID:      "example-host",
        DeviceType: "HOST",
        ServerTrustAnchors: map[string]string{
            "server-key-2026": "<P-256 SPKI Base64URL>",
        },
        IdentityStore: sc.FileIdentityStore{
            Path: filepath.Join(configDir, "example-app", "sc-v2-identity.json"),
        },
    })
}

func send(client *sc.Client, payload []byte, requestID string) (*sc.Response, error) {
    ctx, cancel := context.WithTimeout(context.Background(), 15*time.Second)
    defer cancel()
    return client.Request(ctx, sc.Request{
        Method: "POST", LogicalPath: "/attach/upload",
        ContentType: "application/json",
        ProtectedHeaders: map[string]string{"code": "host-version"},
        Body: payload, RequestID: requestID,
    })
}
```

首次安装时由宿主通过运行时环境或回调取得短时注册令牌：

```go
if err := client.Enroll(os.Getenv("SC_ENROLLMENT_TOKEN")); err != nil {
    return err
}
if err := client.Initialize(ctx); err != nil {
    return err
}
```

注册成功后 SDK 清除内存中的令牌，后续握手使用安装私钥证明。令牌不得写入身份
文件、日志或构建产物。`FileIdentityStore` 创建目录权限为 `0700`、文件权限为


## 10. 注册令牌流程

H5 不使用注册令牌。HOST、SERVER、EMULATOR、ANDROID、IOS 的新安装必须提供短时、单次
使用令牌：

1. 受管理后台调用宿主实现的管理接口，例如
   `POST /admin/sc/v1/enrollment-tokens`；
2. 后台按 `appId`、`deviceType` 和有效期调用
   `EnrollmentTokenService.issue(...)`；
3. 宿主应用通过环境变量或初始化回调把令牌传给 `enroll(token)`；
4. SDK 在首次握手中使用令牌，服务端原子消费并登记安装公钥；
5. 后续握手只使用安装私钥持有证明。

建议有效期为 5 至 15 分钟，SDK 实现允许的最大 TTL 为 1 小时。管理接口本身必须
在内部网络或强管理认证之后，不能直接暴露给公网。

## 11. 请求、重试与会话语义

### 11.1 requestId 与业务幂等 ID

传输 `seq` 仅防重放，`requestId` 用于关联一次加密传输；它们不等于业务
`messageId`、`batchId` 或业务 sequence。

网络超时后不要原样重发密文。正确流程是：

1. 保留原业务 `messageId`、`batchId` 和业务顺序字段；
2. 生成新的传输 `requestId`；
3. 由 SecureClient 取得新的 `seq` 并重新加密；
4. 由现有业务幂等逻辑判断是否重复处理。

SDK 不自动重试业务 POST。`SC_UNKNOWN_SESSION` 表示需要重新握手；完成握手后，仍
应由业务层决定是否重发。

### 11.2 会话生命周期

`initialize()` 是幂等的：会话有效时直接复用，过期后重新握手。需要主动释放当前
会话时调用 `closeSession()`。它不会删除长期安装身份。

客户端时钟与服务端偏差超过 `clock-skew` 会导致握手失败或
`SC_REQUEST_EXPIRED`，部署环境应启用可靠的时间同步。

## 12. 本地端到端调试

### 12.1 推荐环境变量

以下是宿主应用可采用的本地配置约定；具体环境变量名由宿主实现映射：

```bash
export SC_ENABLED=true
export SC_REQUIRE_TLS=false
export SC_SERVER_KEY_ID=server-key-dev
export SC_SERVER_PRIVATE_KEY='<P-256 PKCS8 Base64URL>'
export SC_SERVER_PUBLIC_KEY='<P-256 SPKI Base64URL>'
export SC_SESSION_RECORD_KEY='<32字节 Base64URL>'
export SC_ALLOWED_APP_IDS=example-web-dev
export SC_ENROLLMENT_ADMIN_TOKEN='<随机管理令牌>'
export SC_CORS_ALLOWED_ORIGINS='http://localhost:8888,http://127.0.0.1:8888'
export REDIS_HOST=127.0.0.1
export REDIS_PORT=6379
export REDIS_PASSWORD='<Redis 实际密码；无密码时留空>'
```

这些是跨语言示例环境变量，不会被任一 SDK 自动识别。宿主需要把它们映射到 Spring
Bean/属性、Go `Config`/构造参数或 Python `Config`/构造参数。私钥和密码不要提交到
`.env` 模板的真实值中。

### 12.2 启动与检查顺序

1. 检查 Redis 连接和认证：

   ```bash
   redis-cli -h 127.0.0.1 -p 6379 -a "$REDIS_PASSWORD" ping
   ```

   期望返回 `PONG`。如果 Redis 无密码，不传 `-a`。

2. 启动所选服务端并确认端口（三选一）：

   ```bash
   # Spring Boot
   mvn spring-boot:run
   lsof -nP -iTCP:11099 -sTCP:LISTEN

   # Go Demo（默认仅验证工程；完整联调需由宿主装配身份与状态）
   go run ./cmd/demo
   lsof -nP -iTCP:6789 -sTCP:LISTEN

   # Python Demo（默认仅验证工程；完整联调需由宿主装配身份与状态）
   uvicorn demo.app:app --host 127.0.0.1 --port 6789
   lsof -nP -iTCP:6789 -sTCP:LISTEN
   ```

3. 启动 H5 Demo 页面：

   ```bash
   npx http-server ./demo -p 8888
   ```

4. 打开浏览器 DevTools：

   - Console 不应出现初始化异常；
   - Network 应出现 handshake、finish、message；
   - 三个请求的 OPTIONS 预检应返回允许当前 Origin；
   - `/message` 的外层请求中看不到业务明文和 `code`；
   - 服务端 Controller 收到的 body/header 应与改造前一致。

5. 清除站点 IndexedDB 后刷新，验证新安装身份流程；等待或缩短 session TTL，验证
   会话到期后自动重新握手。

## 13. 常见错误排查

| 现象/错误 | 常见原因 | 排查与修复 |
| --- | --- | --- |
| `appId is required` | 客户端初始化配置缺少 `appId` | 在创建客户端时提供服务端白名单允许的非空 `appId` |
| `serverTrustAnchors is required` / `Untrusted server identity` | 未配置 keyId，或服务端返回 keyId 不在信任锚中 | 对比服务端 `serverKeyId` 和客户端 map key |
| `Server identity pin mismatch` | 客户端 SPKI 与服务端公钥不一致，或误用了 PEM 文本/PKCS#8 | 使用公钥 SPKI DER 的 Base64URL，无 `=` padding |
| `baseUrl must use HTTP or HTTPS` | URL 协议不是 HTTP(S)，或 URL 含凭据、query、fragment | 使用合法的 HTTP/HTTPS 服务根地址；业务 query 放入逻辑 path |
| `SC_CRYPTO_UNAVAILABLE` | H5 页面所在 HTTP 环境不是浏览器安全上下文 | 使用 HTTPS、浏览器认可的本地安全上下文或企业受管浏览器策略 |
| 预检缺少 `Access-Control-Allow-Origin` | Origin 不匹配，或 CORS Filter 顺序晚于安全 Filter/Security | 核对协议、host、端口；把 CORS Filter order 设为小于 `-200` |
| handshake 成功但 message 被 CORS 拦截 | 只给握手 Controller 配了 CORS，未覆盖 `/sc/v1/message` | 给 `/sc/v1/**` 注册早期 `CorsFilter`，允许 `POST, OPTIONS` 和 `Content-Type` |
| handshake 返回 404 | 服务端 SDK 未启用/未装配、握手路由未注册或 baseUrl 错误 | Spring 检查 Starter 与 `spring.sc.enabled`；Go 检查 `httpadapter`；Python 检查 `install_fastapi_routes` |
| `SC_HANDSHAKE_FAILED` | appId/Origin/deviceType 不允许，安装密钥变化，服务端签名或时间校验失败 | 查服务端分类日志；不要把具体鉴权细节返回客户端 |
| `SC_ENROLLMENT_REQUIRED` | 原生/Host 新安装未提供令牌，或令牌过期/已消费/appId 不匹配 | 重新签发短时单次令牌并调用 `enroll` |
| `SC_KEY_PROVIDER_UNAVAILABLE` | Redis 未启动/密码错误、会话记录密钥错误、KMS/私钥不可用 | 先执行 Redis `PING`；检查认证、密钥长度和服务端 provider 日志 |
| `SC_REPLAY_STORE_UNAVAILABLE` | Redis 重放保护无法原子写入 | 恢复 Redis 后使用新的 requestId/seq 重新加密；请求未下发业务层 |
| `SC_UNKNOWN_SESSION` | 会话过期、被撤销或 Redis 会话丢失 | `closeSession()` 后重新握手，再由业务层决定是否重发 |
| `SC_REPLAY_DETECTED` | 重复发送同一个加密信封/seq | 不要重发旧密文；生成新的 requestId 并重新加密 |
| `SC_REQUEST_EXPIRED` | 客户端时钟偏差或请求积压过久 | 同步系统时间并创建新请求 |
| `SC_AUTHENTICATION_FAILED` | 密文/AAD 被篡改，或会话密钥不一致 | 丢弃请求、关闭会话；禁止降级到明文或旧协议 |
| `SC_ROUTE_MISMATCH` | 外层固定路由错误，或逻辑路由不在白名单 | 外层只调用 `/sc/v1/message`；检查 method/path 白名单 |
| `SC_PAYLOAD_TOO_LARGE` | 外层信封、明文或 body 超限 | 在业务层分批，或在风险评估后同步调整服务端限制 |

浏览器报 `TypeError: Failed to fetch` 时，优先查看该请求之前的红色 CORS 或网络
错误；Fetch 会隐藏被 CORS 拦截的响应正文，不能只依赖 JavaScript 堆栈定位。

## 14. 日志与可观测性

安全链路日志仅记录：

- `requestId`；
- `appId`；
- session ID 摘要，不记录完整 sid；
- suite；
- 安全错误分类；
- 握手和请求耗时。

禁止记录明文 body、受保护 header 值、私钥、会话密钥、完整信封、注册令牌或完整
安装身份。客户端可上报错误 code、HTTP status 和 trace ID，但不要上报密钥材料。

建议指标至少包含握手成功率、按分类统计的失败数、会话创建数、重放拒绝数、超限
拒绝数、Redis/KMS 可用性和 p95/p99 延迟。不要把高基数 sid 作为指标标签。

## 15. 上线检查清单

- [ ] 已由企业明确选择 HTTP 或 HTTPS；生产优先使用 HTTPS，TLS 最低版本为 1.2。
- [ ] 需要强制 HTTPS 的服务端已配置 `require-tls=true` / `RequireTLS=true` / `require_tls=True`。
- [ ] 服务端私钥来自 KMS/HSM 或受控密钥文件，不在源码、镜像层和配置中心明文中。
- [ ] 客户端信任锚的 keyId、公钥和指纹已通过独立渠道核对。
