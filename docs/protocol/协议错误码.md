# 协议 v1 错误码

| HTTP | Code | 分类 | 含义与处理 |
| --- | --- | --- | --- |
| 400 | `SC_INVALID_ENVELOPE` | 协议 | 信封格式错误、字段缺失/多余、重复字段、编码或 nonce 非法 |
| 400 | `SC_ROUTE_MISMATCH` | 协议 | 固定外层绑定或解密后的逻辑路由不合法 |
| 400 | `SC_TLS_REQUIRED` | 传输 | 协议 v1 请求没有运行在受认证 TLS 上 |
| 401 | `SC_HANDSHAKE_FAILED` | 握手 | 身份、证明或准入失败；服务端有意隐藏具体原因 |
| 401 | `SC_ENROLLMENT_REQUIRED` | 注册 | 原生新安装缺少有效的短时单次注册令牌 |
| 401 | `SC_UNKNOWN_SESSION` | 会话 | `kid`/`sid` 未知、过期或已撤销，需要重新握手 |
| 401 | `SC_AUTHENTICATION_FAILED` | 密码 | AEAD 认证失败，不能降级或原样重试 |
| 408 | `SC_REQUEST_EXPIRED` | 时间 | 时间戳超出允许窗口，应同步时钟并创建新请求 |
| 409 | `SC_REPLAY_DETECTED` | 重放 | 传输序号已被接受，不能再次发送 |
| 413 | `SC_PAYLOAD_TOO_LARGE` | 策略 | 外层信封、保护明文或业务 body 超限 |
| 426 | `SC_UNSUPPORTED_VERSION` | 策略 | 协议版本不受支持 |
| 426 | `SC_UNSUPPORTED_SUITE` | 策略 | 密码套件不可用或未被策略允许 |
| 503 | `SC_KEY_PROVIDER_UNAVAILABLE` | 服务 | KMS、HSM、会话或注册状态提供方不可用，可进行有界重试 |
| 503 | `SC_REPLAY_STORE_UNAVAILABLE` | 服务 | 原子重放存储不可用，请求没有交付给业务层 |
| 500 | `SC_INTERNAL_ERROR` | 服务 | 内部失败，不暴露密码学细节 |

所有服务端实现返回相同结构：

```json
{
  "code": "SC_INVALID_ENVELOPE",
  "message": "Secure envelope is invalid",
  "traceId": "opaque-trace-id"
}
```

`message` 是稳定、非敏感的英文协议消息。各平台 SDK 将 `code` 映射为统一错误类型，
同时保留 HTTP status 和 trace ID。业务方应主要基于 `code` 决策，不要解析 message。

只有网络短暂失败、`SC_KEY_PROVIDER_UNAVAILABLE` 或业务明确允许的服务错误可进行有界
重试。重试加密业务请求时仍必须生成新序号和新 `rid`；认证失败、重放、路由错误与
不支持的协议/套件不得自动重试或降级。
