# 客户端统一接口契约 v1

本文定义 Secure Communication 客户端 SDK 的公共接口语义。各语言使用惯用的命名、
字节类型和并发原语，但配置、生命周期、请求、响应、错误和安全行为必须一致。线协议
仍由[协议 v1](protocol/协议v1.md)定义，接口契约变更不能隐式改变线协议。

## 生命周期

客户端统一提供创建、`enroll`、`initialize`、`request` 和 `closeSession`：

1. 宿主使用配置创建一个可长期复用、并发安全的客户端；
2. 非 H5 新安装先调用 `enroll(token)`，令牌只驻留内存；
3. `initialize` 建立会话，重复调用复用仍有效的会话；
4. `request(SecureRequest)` 在无有效会话时可以先初始化，但绝不自动重发业务请求；
5. `closeSession` 只清除内存会话，不删除安装身份。

注册令牌只有在握手 finish 成功后才能清除。调用方重试时必须创建一次新的 request
调用，让 SDK 使用新序号、新 request ID 和新密文；业务幂等 ID 保持不变。

## 公共模型

`SecureClientConfig` 的共同字段为：

- `baseUrl`、`appId`、`deviceType`；
- `serverTrustAnchors`，即 `kid -> P-256 SPKI Base64URL`；
- `identityStore`；
- 默认请求超时和允许时钟偏差；
- 可选平台 transport。`baseUrl` 支持 HTTP 和 HTTPS，生产环境建议使用 HTTPS。

`deviceType` 只接受 `H5`、`HOST`、`SERVER`、`ANDROID`、`IOS` 和 `EMULATOR`。
JavaScript、Go、Android、iOS 的平台默认值分别为 `H5`、`HOST`、`ANDROID` 和 `IOS`。

正式高层请求入口只接收一个 `SecureRequest`：

| 字段 | 语义 | 默认值 |
| --- | --- | --- |
| `method` | 逻辑 HTTP method | `GET` |
| `logicalPath` | 逻辑 path 和可选 query，不得是绝对 URL | 必填 |
| `contentType` | 逻辑正文媒体类型 | `application/octet-stream` |
| `protectedHeaders` | 加密的业务 header | 空 map |
| `body` | 原始业务字节 | 空字节 |
| `requestId` | 认证的传输关联 ID | SDK 每次调用生成 |

`SecureResponse` 统一暴露 `status`、`contentType` 和二进制 `body`。语言可额外提供
UTF-8 或 JSON 便利方法，但不能只返回平台原生 HTTP response。

`SecureError` 统一暴露稳定 `code`、`httpStatus`、可选 `traceId` 和底层 `cause`。
错误不得包含正文、令牌、密钥或完整信封。超时使用 `SC_REQUEST_TIMEOUT`；同步取消
或线程中断使用 `SC_REQUEST_CANCELLED`。Promise、Future、Task 或 context 被主动取消时，
也可以先表现为该语言的原生取消异常。
未收到 HTTP 响应时，Go、Java、Android 和 iOS 的 `httpStatus` 使用 `0`；JavaScript
字段为未定义。客户端配置、身份、网络、超时等本地错误不要求映射为服务端 HTTP 状态。

## 身份与执行上下文

身份存储的共同语义为 `loadOrCreate(appId) -> InstallationIdentity`。安装身份提供稳定
device ID、SPKI 公钥和 `sign(data)`，不要求导出私钥，因此同一契约可映射文件、
Android Keystore、Keychain、WebCrypto 或 HSM/KMS。

超时、取消、deadline 等执行控制不属于 `SecureRequest`，通过独立执行选项或语言原生
上下文传递：

| 平台 | 执行方式 | 取消/超时 |
| --- | --- | --- |
| JavaScript | Promise | `AbortSignal` |
| Go | 阻塞方法 | `context.Context` |
| Android | 同步方法或 `SecureCall` | `execute` / `enqueue` / `cancel` |
| iOS | `async/await` | Swift `Task` |
| Java | 阻塞方法和 `CompletableFuture` | `ExecutionOptions`、中断、Future cancel |

并发初始化必须合并为一次握手；同一会话中的并发请求必须取得唯一递增序号。取消一个
等待共享初始化的调用不能破坏其他调用使用的握手。

## 当前符合性和版本

| 客户端 | 当前状态 | 后续迁移 |
| --- | --- | --- |
| Java | 1.1 | 完整实现，含 SERVER 类型 |
| JavaScript | 2.0 | 完整实现；Promise + AbortSignal |
| Go | 2.0 | 完整实现；module path 使用 `/v2` |
| Android | 2.0 | 完整实现；同步入口和可取消 SecureCall |
| iOS | 2.x API | 完整实现；Package.swift 未声明版本，actor + Swift Task |

JavaScript、Go、Android 和 iOS 的 2.0 是破坏性公共 API 升级，只保留统一的
`request(SecureRequest)` 高层入口。四端 2.0 使用新的身份 namespace，不读取、覆盖或
删除 1.x 身份；非 H5 客户端升级后需重新 enrollment。线协议仍为 protocol v1。

此处版本表示当前源码 API 代际。仓库没有 Git tag，不能据此推断远端制品已发布。
