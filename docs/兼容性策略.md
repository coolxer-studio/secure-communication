# 兼容性策略

1.0 是安全通信协议的首个正式版本，不兼容仓库曾存在的共享密钥、SM4-ECB、同步
Socket 或旧 H5 codec 协议。

| 交付物 | 最低环境 | 协议 v1 | 国际套件 | 国密扩展位 |
| --- | --- | --- | --- | --- |
| Spring Boot Server | Java 17、Spring Boot 3 | 支持 | 支持 | Provider 可扩展 |
| Go Server | Go 1.21 | 支持 | 支持 | Provider 可扩展 |
| Python Server | Python 3.9、FastAPI/ASGI | 支持 | 支持 | Provider 可扩展 |
| JavaScript / H5 | 现代浏览器、WebCrypto | 支持 | 支持 | 不首发 |
| Go Host / Emulator | Go 1.21 | 支持 | 支持 | 不首发 |
| Java Host / Emulator | Java 17 | 支持 | 支持 | Provider 可扩展 |
| Android | minSdk 21 | 支持 | 支持 | Provider 可扩展 |
| iOS | 支持 CryptoKit 的 iOS/Xcode | 支持 | 支持 | Provider 可扩展 |

协议版本、suite、`kid`、固定入口或媒体类型不匹配时必须失败，不允许自动降级。服务端
实现可以独立升级，但只有在协议字段与测试向量不变时才能维持 v1 互操作；任何线协议
变更都必须进入新协议版本，并同步更新[协议规范](protocol/协议v1.md)、错误码、测试向量和
全部平台测试。

客户端公共语义由[客户端接口契约](客户端接口契约.md)管理。Java 1.x 与 JavaScript、
Go、Android、iOS 2.0 均提供请求对象入口和统一响应、错误及身份 SPI。2.0 客户端升级
不改变线协议，但不兼容 1.x 公共 API 或身份文件；迁移要求见
[客户端 2.0 迁移指南](客户端2.0迁移指南.md)。

客户端 SDK 不自动重试业务 POST。服务端会话过期或撤销后，客户端重新握手；是否重发
业务由调用方依据幂等语义决定。安全失败不能回退到原明文业务入口。
